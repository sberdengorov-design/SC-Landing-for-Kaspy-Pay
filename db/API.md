# Регистрация с лендинга — контракт API

Форма на лендинге (`index.html`, модальное окно `#reg-modal`) сейчас ничего не
отправляет. Ниже — что она должна вызывать, когда бэкенд появится.

Схема таблиц: [schema.sql](schema.sql).

## Что отправляет форма

Поля анкеты и их значения:

| Поле | Ключ | Значения |
|---|---|---|
| ФИО | `full_name` | строка, минимум два слова |
| ИИН | `iin` | 12 цифр, контрольный разряд проверяется и на клиенте, и на сервере |
| Телефон | `phone` | `7XXXXXXXXXX`, он же логин |
| E-mail | `email` | строка |
| Город | `city` | `astana`, `almaty`, … `oskemen` — 20 значений |
| Пользователь | `user_type` | `binom`, `farabi`, `school`, `teacher` |
| Предмет | `subject` | `math`, `geography`, … `other` — 22 значения |
| Стаж | `experience` | `lt1`, `1-3`, `3-5`, `5-10`, `10-15`, `15-20`, `20-25`, `25-30`, `30+` |
| Категория | `category` | `none`, `moderator`, `expert`, `researcher`, `master` |

Списки значений лежат в скрипте страницы: `CITIES`, `USER_TYPES`, `SUBJECTS`,
`EXPERIENCE`. При изменении справочника на сервере обновить и их.

## POST /api/registration

Приём анкеты и отправка кода на телефон.

```json
{ "full_name": "…", "iin": "990101123456", "phone": "77012345678",
  "email": "…", "city": "almaty", "user_type": "teacher",
  "subject": "geography", "experience": "10-15", "category": "expert",
  "consent": true }
```

Ответы:

| Код | Когда | Тело |
|---|---|---|
| `202` | код отправлен | `{ "expires_in": 300 }` |
| `409 org_managed` | `user_type` не `teacher` | самостоятельная регистрация запрещена, аккаунт заводит администратор через АУП |
| `409 iin_taken` | ИИН уже в системе | предложить вход |
| `409 phone_taken` | телефон уже логин | предложить вход |
| `422` | не прошла валидация | список полей с ошибками |
| `429` | частые запросы кода | `Retry-After` |

Сервер обязан перепроверить контрольный разряд ИИН: клиентская проверка
защищает от опечатки, а не от подделки.

## POST /api/registration/confirm

```json
{ "phone": "77012345678", "code": "1234" }
```

При верном коде: создаётся `teacher` с `source = 'self'`, запись в `trial`
(3 анализа, 30 дней) и запись в `consent`. Строка `otp_code` удаляется вместе
с анкетой.

| Код | Когда |
|---|---|
| `201` | аккаунт создан, тело — токен сессии и остаток квоты |
| `400 bad_code` | код не совпал, счётчик `attempts` увеличен |
| `410 expired` | код просрочен или исчерпаны 5 попыток |

## GET /api/trial/quota

Для показа остатка в личном кабинете.

```json
{ "limit": 3, "used": 1, "expires_at": "2026-09-06T00:00:00Z", "open": true }
```

## Почему квоту нельзя считать на лендинге

Любой счётчик в браузере обходится очисткой хранилища или режимом инкогнито.
Списание привязано к вставке строки в `lesson_analysis`: триггер
`spend_trial_analysis` уменьшает остаток и на нуле проставляет `blocked_at`.
Обойти это можно только через базу.

## Персональные данные

* ИИН, ФИО и телефон граждан РК хранятся на серверах в Казахстане —
  требование закона «О персональных данных». GitHub Pages и любой зарубежный
  хостинг для базы не подходят.
* ИИН в открытом виде не хранится: `iin_hash` для уникальности и поиска,
  `iin_enc` — шифротекст.
* Без записи в `consent` регистрацию не завершать. На форме нужен чекбокс
  согласия со ссылкой на политику — сейчас его нет, добавить вместе с
  подключением API.
* Коды подтверждения хранятся хешами, срок жизни 5 минут, не больше
  5 попыток ввода.
